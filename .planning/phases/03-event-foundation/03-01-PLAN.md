**Events table schema:**
- id (UUID, primary key, auto-generated)
- owner_id (UUID, references auth.users, NOT NULL)
- type (TEXT, CHECK constraint: 'jam', 'class', 'workshop', 'convention')

**Shared required fields:**
- title (TEXT, NOT NULL)
- location_text (TEXT, NOT NULL)
- starts_at (TIMESTAMPTZ, NOT NULL)
- ends_at (TIMESTAMPTZ, NOT NULL)

**Shared optional fields:**
- description (TEXT)
- price (TEXT) -- Free-form: "Free", "€20", "$10-15"
- external_link (TEXT)
- organizer_contact (TEXT)

**Location fields (all optional):**
- location_lat (NUMERIC)
- location_lng (NUMERIC)
- location_place_id (TEXT)
- gmaps_link (TEXT)

**Status management:**
- status (event_status ENUM: 'draft', 'published', 'archived', default 'draft')

**Timestamps:**
- created_at (TIMESTAMPTZ, default NOW())
- updated_at (TIMESTAMPTZ, default NOW())

**Why this structure:** Single table with type discriminator is PostgreSQL best practice for 4 similar entity types. All events share core fields (title, location, dates). Type-specific fields can be added later as regular columns (not JSONB - research shows JSONB unnecessary for current requirements).

**Indexes for RLS performance:**
- idx_events_owner_id ON events(owner_id)
- idx_events_type ON events(type)
- idx_events_status ON events(status)
- idx_events_starts_at ON events(starts_at)

**Create event_status ENUM before table creation.**

<task type="auto">
  <name>Task 3: Create RLS policies and authorization function</name>
  <files>apps/web/supabase/migrations/20260121000000_create_events_tables.sql</files>
  <action>
Add RLS policies to the same migration file (append after tables). Follow the exact pattern from jam_managers RLS policies.

**Enable RLS:**
ALTER TABLE public.events ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.event_organizers ENABLE ROW LEVEL SECURITY;

**Events RLS policies:**
1. "Anyone can view published events" - SELECT policy: status = 'published' OR owner_id = auth.uid() OR is_event_owner_or_organizer(id, auth.uid()) OR public.is_admin(auth.uid())
2. "Users can create events" - INSERT policy: auth.uid() = owner_id
3. "Owners and co-organizers can update events" - UPDATE policy: owner_id = auth.uid() OR is_event_owner_or_organizer(id, auth.uid()) OR public.is_admin(auth.uid())
4. "Owners and admins can delete events" - DELETE policy: owner_id = auth.uid() OR public.is_admin(auth.uid())

**Event_organizers RLS policies (mirror jam_managers):**
1. "Owners and organizers can view organizers" - SELECT policy
2. "Owners and organizers can add organizers" - INSERT policy
3. "Owners and organizers can remove organizers" - DELETE policy

**Authorization function (mirror is_owner_or_manager):**
CREATE OR REPLACE FUNCTION public.is_event_owner_or_organizer(event_id UUID, user_id UUID)
RETURNS BOOLEAN
LANGUAGE SQL
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT EXISTS (
    SELECT 1 FROM public.events
    WHERE events.id = is_event_owner_or_organizer.event_id
      AND (events.owner_id = is_event_owner_or_organizer.user_id OR EXISTS (
        SELECT 1 FROM public.event_organizers
        WHERE event_organizers.event_id = events.id
          AND event_organizers.user_id = is_event_owner_or_organizer.user_id
      ))
  );
$$;

**Why SECURITY DEFINER:** Function needs elevated privileges to check ownership/organizer status regardless of RLS policies. Standard Supabase pattern for authorization helpers.

**Pitfall to avoid:** Super admin check is handled by separate is_admin() function - don't duplicate logic. RLS policies call both functions with OR.
