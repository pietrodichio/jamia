**Step 2: Backend DTO** (`apps/backend/src/email-preferences/dto/update-email-preferences.dto.ts`)

Create class with class-validator decorators. Follow the pattern from `update-profile.dto.ts`:
- `@IsBoolean() @IsOptional() digest_enabled?: boolean;`
- `@IsIn(['weekly', 'monthly']) @IsOptional() digest_frequency?: 'weekly' | 'monthly';`

Implement the shared `UpdateEmailPreferencesDto` interface from `@jamia/types`.

**Step 3: Backend Service** (`apps/backend/src/email-preferences/email-preferences.service.ts`)

Follow the profiles.service.ts pattern exactly. Inject `SUPABASE_CLIENT`. Three methods:

1. `getPreferences(userId: string)` -- SELECT from email_preferences WHERE user_id = userId, `.single()`. Throw `NotFoundException` if no row found.

2. `updatePreferences(userId: string, dto: UpdateEmailPreferencesDto)` -- UPDATE email_preferences SET dto fields WHERE user_id = userId, `.select().single()`. Throw error on failure. IMPORTANT: Always send both `digest_enabled` and `digest_frequency` together from the frontend to avoid race conditions (Pitfall 3 from RESEARCH.md), but the DTO allows partial updates for flexibility.

3. `unsubscribeByToken(token: string)` -- UPDATE email_preferences SET digest_enabled = false WHERE unsubscribe_token = token, `.select().single()`. Throw `NotFoundException` if token not found (data is null or error).

Add `private readonly logger = new Logger(EmailPreferencesService.name);` for logging.

**Step 4: Backend Controller** (`apps/backend/src/email-preferences/email-preferences.controller.ts`)

Follow profiles.controller.ts pattern:
- `@Controller('email-preferences')`
- `@UseGuards(SupabaseAuthGuard)` at class level
- Inject `EmailPreferencesService`

Endpoints:
1. `@Get()` -- calls `getPreferences(user.id)`. Uses `@User() user: AuthUser` decorator.
2. `@Patch()` -- calls `updatePreferences(user.id, dto)`. Uses `@User()` and `@Body(new ValidationPipe({ transform: true }))`.
3. `@Public() @Post('unsubscribe/:token')` -- calls `unsubscribeByToken(token)`. Returns `{ message: 'Unsubscribed successfully' }`. The `@Public()` decorator bypasses the class-level auth guard.
4. `@Public() @Get('unsubscribe/:token')` -- same as POST, for browser-based one-click unsubscribe. Also returns `{ message: 'Unsubscribed successfully' }`.

CRITICAL: The `@Public()` decorator on unsubscribe endpoints is essential -- email clients POST directly to unsubscribe URLs without auth tokens. Import `@Public()` from `'../auth/public.decorator'`.

IMPORTANT: Place the `unsubscribe/:token` routes BEFORE any parameterized routes to avoid route conflicts. Since there are no other parameterized routes on this controller, just ensure `unsubscribe` paths are defined after the root `@Get()` and `@Patch()`.
