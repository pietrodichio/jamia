The migration must include ALL of the following in this order:

1. **Create the table:**
```sql
CREATE TABLE IF NOT EXISTS public.email_preferences (
  user_id UUID PRIMARY KEY REFERENCES public.profiles(id) ON DELETE CASCADE,
  digest_enabled BOOLEAN NOT NULL DEFAULT false,
  digest_frequency TEXT NOT NULL DEFAULT 'monthly'
    CHECK (digest_frequency IN ('weekly', 'monthly')),
  unsubscribe_token UUID NOT NULL DEFAULT gen_random_uuid(),
  last_digest_sent_at TIMESTAMPTZ,
  has_seen_digest_prompt BOOLEAN NOT NULL DEFAULT false,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

Add table and column comments explaining purpose (match existing codebase convention from base_schema.sql).

2. **Create indexes:**
- Partial index on `(digest_enabled, digest_frequency) WHERE digest_enabled = true` for Phase 8 digest scheduling queries
- Unique index on `unsubscribe_token` for fast token lookups

3. **Enable RLS and create policies:**
- Enable RLS on the table
- "Users can view own email preferences" -- SELECT for authenticated where `auth.uid() = user_id`
- "Users can update own email preferences" -- UPDATE for authenticated where `auth.uid() = user_id`
- "Users can insert own email preferences" -- INSERT for authenticated with check `auth.uid() = user_id`
- Note: Service role bypasses RLS by default (needed for Phase 8 scheduler), so no extra policy needed

4. **Add updated_at trigger** using the existing `update_updated_at()` function (already defined in base_schema.sql for jams):
```sql
CREATE TRIGGER update_email_preferences_updated_at
  BEFORE UPDATE ON public.email_preferences
  FOR EACH ROW EXECUTE FUNCTION public.update_updated_at();
```

5. **Update handle_new_user() trigger** to also insert into email_preferences when a new user signs up. Use `CREATE OR REPLACE FUNCTION` to redefine it. The current version (from migration 20251022) inserts into profiles and user_roles. Add a third INSERT for email_preferences with `digest_enabled = false, digest_frequency = 'monthly'`.

6. **Backfill existing users:**
```sql
INSERT INTO public.email_preferences (user_id, digest_enabled, digest_frequency)
SELECT p.id, false, 'monthly'
FROM public.profiles p
WHERE NOT EXISTS (
  SELECT 1 FROM public.email_preferences ep WHERE ep.user_id = p.id
);
```

IMPORTANT: The backfill MUST come after the table creation and BEFORE any queries that assume all users have preferences.
