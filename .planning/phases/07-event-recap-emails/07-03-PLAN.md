**Step 1: API client** (`apps/web/src/api/email-preferences.api.ts`)

Follow the pattern from `profiles.api.ts` exactly. Import `apiClient` from `'./client'` and types from `'@jamia/types/email-preferences'`.

```typescript
export const emailPreferencesApi = {
  getPreferences: async (): Promise<EmailPreferencesResponse> => {
    const response = await apiClient.get('/email-preferences');
    return response.data;
  },

  updatePreferences: async (dto: UpdateEmailPreferencesDto): Promise<EmailPreferencesResponse> => {
    const response = await apiClient.patch('/email-preferences', dto);
    return response.data;
  },
};
```

No unsubscribe method needed on the frontend -- unsubscribe is handled via direct URL in emails.

**Step 3: EmailPreferencesCard component** (`apps/web/src/components/settings/EmailPreferencesCard.tsx`)

Create a self-contained card component that manages its own data fetching and mutations via React Query. This is NOT part of the profile form -- it operates independently with its own API calls.

Component structure:
- Uses `useQuery` to fetch current preferences from `emailPreferencesApi.getPreferences()`
- Uses `useMutation` to save changes via `emailPreferencesApi.updatePreferences()`
- Query key: `['email-preferences']`
- Enabled only when `userId` prop is truthy

Props: `{ userId: string; isNewUser?: boolean }`
- `isNewUser` defaults to `false`. When `true`, the component shows the toggle as ON by default (pre-checked) even before the first API response arrives, and auto-saves `{ digest_enabled: true, digest_frequency: 'monthly' }` on mount. This handles the CONTEXT.md requirement: "New users: Ask during signup with pre-checked toggle (opt-out pattern)."

UI layout (inside a Card from shadcn/ui):
1. CardHeader with title "Notifiche Email" and description (use `t('common:emailPreferences.title')` etc.)
2. CardContent with:
   a. A `div` with flex justify-between containing:
      - Left side: Label "Ricezione digest" + small description text
      - Right side: `<Switch>` component
   b. When digest is enabled, show a `<RadioGroup>` below with two options:
      - "Settimanale" with sub-text "Ogni lunedi mattina"
      - "Mensile" with sub-text "Il primo di ogni mese"
      - Use smooth CSS transition for show/hide (e.g., `overflow-hidden transition-all duration-200`)

**Mutation behavior:**
- On Switch toggle: call `updatePreferences({ digest_enabled: newValue, digest_frequency: currentFrequency })`. ALWAYS send BOTH fields together to avoid race conditions (Pitfall 3 from RESEARCH.md).
- On RadioGroup change: call `updatePreferences({ digest_enabled: true, digest_frequency: newValue })`.
- On success: invalidate `['email-preferences']` query, show toast with title "Preferenze salvate".
- On error: show destructive toast with error message.

**Loading state:** Show a skeleton or disabled state while `isLoading` from useQuery is true. The Switch and RadioGroup should be `disabled={isLoading || mutation.isPending}`.

Use `useTranslation('common')` for all text. Import from `react-i18next`.
