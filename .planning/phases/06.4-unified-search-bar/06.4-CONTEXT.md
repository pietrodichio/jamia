# Phase 6.4 Context: Unified Search Bar

## User Requirements (from conversation)

### Structure
- Merge KeywordSearch + LocationSearch into one unified component
- Keep vertical divider between them
- Single circular search button that triggers location-based search
- Layout: `[🔍 Keyword input] | [📍 Location input] [🔵 Search button]`

### Location Dropdown Behavior
- NO "Online events" option (we don't have online events)
- Default value is **prefilled with IP-based location** (from Phase 6.3's useIpLocation hook)
- "Use current location" menu option triggers **GPS browser permission request**
- Autocomplete powered by Google Places API with these restrictions:
  - ALLOWED: cities, countries, states, regions, provinces, neighborhoods
  - NOT ALLOWED: exact places/addresses, zip codes
  - When user enters disallowed values, the input gets cleared after internal evaluation

### Location Display
- Always show **city name only** (e.g., "Milano" not "Milano, Italia")
- Keep "(approssimativa)" indicator for IP-based location
- When using GPS or city search, just show the city name without indicator

### Search Trigger Behavior
- **Keyword search:**
  - Real-time filtering with debounce as user types
  - Enter key also triggers search
- **Location search:**
  - Selection does NOT auto-search (just updates the input display)
  - ONLY search button click triggers location-based search
  - This is intentional UX - user picks location, then explicitly searches

### Filters Integration
- Filters (UnifiedFilters component) stay **separate** below the search bar
- NOT integrated into the search bar

### Mobile Layout
- Stack inputs **vertically** on mobile (like Eventbrite)
- Use **modal/sheet pattern** for search interface on mobile
- Reference: Eventbrite mobile search UX

## Google Places API Configuration

For location autocomplete, need to configure:
- `types: ['(regions)']` - This includes cities, countries, states, regions, provinces, neighborhoods
- NOT `types: ['address']` or `types: ['establishment']`

Need to validate/filter results client-side to reject:
- Zip codes (postal codes)
- Exact street addresses
- Specific places/establishments
