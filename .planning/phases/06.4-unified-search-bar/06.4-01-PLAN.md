Create UnifiedSearchBar.tsx with Eventbrite-style horizontal layout:

**Structure:**
```
[🔍 Keyword input] | [📍 Location input ▼] [🔵 Search button]
```

**Component Architecture:**
1. Use `useIsMobile()` hook - this plan implements desktop only (return null for mobile, Plan 02 adds mobile)
2. Use `useEventFilters()` for URL-based state management
3. Use `useIpLocation()` for IP-based location prefill
4. Use `useGoogleMaps()` for Places API loading

**Layout (Desktop):**
- Container: `flex items-center h-12 border rounded-full bg-background shadow-sm`
- Keyword section: flex-1, Search icon, input with placeholder "Cerca eventi"
- Vertical Separator between sections
- Location section: flex-1, MapPin icon, input showing current location, dropdown below
- Circular search button: `h-10 w-10 rounded-full bg-primary text-primary-foreground`

**State Management:**
- `keywordValue`: local state for keyword input (controlled)
- `locationDisplayText`: computed from locationType (ip/gps/city) and cityName
- `pendingLocation`: { lat, lng, city, type } - staged location before search button click
- `isLocationDropdownOpen`: boolean for dropdown visibility
- `predictions`: Google Places autocomplete results
- `isLoadingPredictions`: loading state for autocomplete

**Keyword Input Behavior:**
- Real-time debounce (300ms) updates URL `query` param via `updateFilter('query', term)`
- Use `useDebouncedCallback` from 'use-debounce' (same as KeywordSearch.tsx)
- Enter key also triggers search (no special handling needed, debounce handles it)

**Location Input Behavior:**
- On mount: If no existing lat/lng in URL, prefill from IP location
- Display text logic:
  - IP location: `${city} (approssimativa)`
  - GPS location: city name only (or coordinates if no city)
  - City search: city name only
- Input is read-only display - clicking opens dropdown
- Selection from dropdown stages pendingLocation (does NOT update URL)
- ONLY search button click applies pendingLocation to URL filters

**Location Dropdown Structure:**
1. "Usa la mia posizione attuale" option with Crosshair icon (triggers GPS)
2. Separator
3. City autocomplete suggestions (max 5)
4. Input field at top for typing city search

**Google Places Autocomplete:**
- Reuse pattern from CitySearchInput.tsx
- Use `types: ['(cities)']` for cities only
- 350ms debounce on search text
- Extract city name from addressComponents (locality fallback to first part before comma)
- On selection: set pendingLocation, close dropdown

**GPS Request:**
- Reuse pattern from LocationSearch.tsx `requestPreciseLocation`
- On success: set pendingLocation with type 'gps', show toast
- On error: show toast with appropriate message

**Search Button:**
- Disabled when pendingLocation is null AND no existing URL location
- On click: apply pendingLocation to URL (lat, lng params), then trigger refetch
- Visual: circular, bg-primary, Search icon

**Translations (add to events.json):**
- `search.keyword.placeholder`: "Cerca eventi"
- `search.location.placeholder`: "Scegli una citta"
- `search.location.useCurrentLocation`: "Usa la mia posizione attuale"
- `search.location.approximate`: "(approssimativa)"
- `search.button.search`: "Cerca"

**Important Implementation Details:**
- Use session tokens for Google Places billing optimization (see CitySearchInput.tsx pattern)
- Handle click outside to close dropdown
- Keyboard navigation in dropdown (ArrowUp/Down, Enter, Escape)
- Prevent form submission on Enter in keyword input
- Use `cn()` for conditional class merging

Enhance UnifiedSearchBar with proper state coordination between IP/GPS/City locations:

**Location Type Tracking:**
- Track `locationType: 'ip' | 'gps' | 'city' | null` in local state
- Update locationType when:
  - IP location auto-applied: 'ip'
  - GPS permission granted: 'gps'
  - City selected from autocomplete: 'city'

**IP Location Auto-Apply Logic:**
- Use `useRef` to track `hasAutoApplied` (prevent re-apply after user clears)
- Only auto-apply on mount when:
  - No existing lat/lng in URL filters
  - IP location is ready
  - hasAutoApplied is false
- After auto-apply: set hasAutoApplied = true, set locationType = 'ip'

**Display Text Formatting:**
- IP: `${city} (approssimativa)` - use translation key
- GPS: just city name (reverse geocode if available) or "Posizione precisa"
- City: just city name from selection

**Pending vs Applied Location:**
- `pendingLocation`: staged before search button click
- Applied location: already in URL params (filters.lat, filters.lng)
- Visual difference:
  - If pendingLocation differs from URL location, show subtle indicator (e.g., dot or changed styling)

**Clear Location Functionality:**
- Small X button next to location input when location is set
- On click: clear URL lat/lng, clear pendingLocation, set hasAutoApplied=true (prevent re-apply)

**Search Button Click Handler:**
```typescript
const handleSearch = () => {
  if (pendingLocation) {
    updateFilter('lat', pendingLocation.lat.toString());
    updateFilter('lng', pendingLocation.lng.toString());
    setLocationType(pendingLocation.type);
    // No need to setPendingLocation(null) - it stays as "current"
  }
  // If no pending and no URL location, button should be disabled
};
```

**Edge Cases:**
- If user has URL location and types new city: pendingLocation updates, applied location unchanged
- If user clicks search: pendingLocation becomes applied
- If user clicks X clear: both cleared, disabled search button
- If user leaves page and returns: URL location restored, display shows that location

**Accessibility:**
- Dropdown has role="listbox"
- Options have role="option" and aria-selected
- Location input has aria-expanded for dropdown state
- Focus management: focus first option when dropdown opens
