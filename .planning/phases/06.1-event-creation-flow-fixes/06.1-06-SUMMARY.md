## Decisions Made

**Conditional step rendering based on event type**
- Rationale: Teachers are only relevant for class/workshop/convention events, not jams. Showing the step conditionally keeps the wizard clean and focused.

**Batch teacher insertion via Promise.all**
- Rationale: Backend lacks batch endpoint. Client-side Promise.all over individual POST requests is simpler than adding backend batch endpoint for this use case.

**Load selected teachers on mount**
- Rationale: Preserves teacher selection when user navigates back from preview step, preventing data loss and maintaining wizard state.

**Clear search after selection**
- Rationale: Improves UX by resetting search field, making it obvious the teacher was added and ready for next search.
