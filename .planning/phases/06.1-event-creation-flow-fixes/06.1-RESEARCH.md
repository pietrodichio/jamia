# Phase 6.1: Event Creation Flow Fixes - Research

**Researched:** 2026-01-24
**Domain:** Event creation wizard UI/UX improvements
**Confidence:** HIGH

## Summary

This phase focuses on fixing critical gaps in the event creation wizard that were identified during Phase 6 execution. The research analyzed the existing JamForm.tsx reference implementation, current event wizard structure, and best practices for React Hook Form multi-step wizards.

**Key Findings:**
- JamForm.tsx provides proven patterns for rich text editing (react-quill), Google Maps autocomplete integration, and date/time validation that should be adapted to the wizard
- Current wizard uses basic Input/Textarea components where sophisticated components are needed
- Multi-select tag component already exists and is implemented correctly
- RecurrenceEditor component exists but needs wizard integration for class events
- Image upload capability is missing entirely from wizard but infrastructure exists (event-images bucket, image-utils.ts)
- Teacher selection pattern exists as post-creation feature but should be integrated into creation flow

**Primary recommendation:** Port proven patterns from JamForm.tsx into wizard steps, add missing image upload step, integrate RecurrenceEditor for class type, and fix EventPreviewStep to handle undefined/missing values properly.

**What:** Implement location autocomplete with debounce and session token management
**When to use:** Replace basic Input in EventTypeStep location field

```typescript
  const timeout = setTimeout(async () => {
    const sessionToken = new google.maps.places.AutocompleteSessionToken();
    const { suggestions } = await google.maps.places.AutocompleteSuggestion
```

### Pattern 4: Image Upload Step with Compression

**What:** New wizard step for event image upload using Supabase Storage
**When to use:** Between EventTypeStep and EventScheduleStep (step 2)
**Example:**
```typescript
// EventImageStep.tsx - NEW component
import { useState } from 'react';
import imageCompression from 'browser-image-compression';
import { supabase } from '@/integrations/supabase/client';

const handleImageUpload = async (file: File) => {
  // 1. Validate file type
  if (!['image/jpeg', 'image/png', 'image/webp'].includes(file.type)) {
    throw new Error('Formato non supportato. Usa JPEG, PNG o WebP.');
  }

  // 2. Validate file size (max 5MB)
  if (file.size > 5 * 1024 * 1024) {
    throw new Error('File troppo grande. Massimo 5MB.');
  }

  // 3. Compress image
  const compressed = await imageCompression(file, {
    maxSizeMB: 1,
    maxWidthOrHeight: 1920,
    useWebWorker: true,
  });

  // 4. Generate unique filename
  const filename = `${crypto.randomUUID()}_${file.name}`;

  // 5. Upload to Supabase Storage
  const { data, error } = await supabase.storage
    .from('event-images')
    .upload(filename, compressed);

  if (error) throw error;

  // 6. Return path for form storage
  return data.path; // Store this in form.image_url
};
```

### Pattern 6: Date/Time Validation with Auto-Fill End Time

**What:** Replicate JamForm's date/time state management and auto-calculation
**When to use:** EventScheduleStep date/time fields
**Example:**
```typescript
// Source: JamForm.tsx lines 156-191
// Pattern: When start date/time changes, auto-set end time to +4 hours (or default duration)

useEffect(() => {
  if (!dateFrom || !timeFrom) return;

  const timer = setTimeout(() => {
    const start = combineDateTime(dateFrom, timeFrom);
    const startDate = new Date(start);

    // Propose end time = start + defaultDuration hours
    const proposedEnd = new Date(startDate);
    proposedEnd.setHours(proposedEnd.getHours() + defaultDuration);

    // Don't extend past end of day (23:59)
    const endOfDay = new Date(startDate);
    endOfDay.setHours(23, 59, 0, 0);

    const finalEnd = proposedEnd > endOfDay ? endOfDay : proposedEnd;
    setValue("ends_at", formatDateTimeLocalInput(finalEnd), { shouldDirty: false });
  }, 500);

  return () => clearTimeout(timer);
}, [dateFrom, timeFrom, setValue, defaultDuration]);
```

### Anti-Patterns to Avoid

- **Don't manually parse Google Maps URLs:** Use place.fetchFields API instead of regex parsing
- **Don't skip image compression:** Always compress before upload to reduce storage costs
- **Don't forget session tokens:** Google Maps autocomplete charges per session, not per request
- **Don't store raw HTML:** Sanitize rich text output with DOMPurify before database storage
- **Don't validate non-existent fields:** Only trigger() fields that exist in current step schema

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Rich text editing | Custom contenteditable div | react-quill + quill-emoji | Toolbar, formatting, emoji picker, accessibility all handled |
| Google Maps autocomplete | Fetch API + debounce | Existing JamForm pattern | Session token billing, new API format, debounce, error handling |
| Recurring event rules | Custom date picker loop | rrule + RecurrenceEditor | iCalendar standard, complex edge cases (DST, month boundaries) |
| Image compression | Canvas resize | browser-image-compression | Handles EXIF, maintains aspect ratio, web worker support |
| Multi-step validation | Manual state tracking | React Hook Form trigger() | Already integrated, validates specific fields per step |
| Date/time formatting | Manual string building | date-fns with it locale | Handles Italian formatting, already used in EventPreviewStep |
| Multi-select tags | Checkbox list | Existing MultiSelect component | Search, badges, keyboard navigation already implemented |

**Key insight:** JamForm.tsx is a reference implementation with proven patterns. Don't rebuild what's already working - extract and adapt components.

## Common Pitfalls

### Pitfall 1: WizardStepIndicator Layout Breaks on Mobile
**What goes wrong:** Step labels overflow or separator lines misalign on small screens
**Why it happens:** Fixed width circles + flex-1 separators + long labels
**How to avoid:** Use responsive classes, hide labels on mobile (show only step numbers)
**Warning signs:** Horizontal scrolling, overlapping text, broken separators
**Current status:** Lines 48-63 already implement mobile/desktop pattern correctly - verify spacing is consistent

### Pitfall 2: Google Maps API Quota Exceeded
**What goes wrong:** High API costs from excessive autocomplete requests
**Why it happens:** No debounce or creating new session token per keystroke
**How to avoid:**
- Debounce input by 350ms (JamForm.tsx line 303)
- Create session token per autocomplete series, not per request
- Only fetch predictions when input.length >= 3
**Warning signs:** Console errors about quota, unexpected Google Cloud bills

### Pitfall 3: Conditional Fields Not Unregistering
**What goes wrong:** Hidden field validation errors block step progression
**Why it happens:** React Hook Form keeps field registration when component unmounts
**How to avoid:** Already solved - useEventWizard uses `shouldUnregister: true` (line 58)
**Warning signs:** "Field X is required" error when X isn't visible

### Pitfall 4: Rich Text XSS Vulnerabilities
**What goes wrong:** Malicious HTML/JavaScript stored and executed in event descriptions
**Why it happens:** react-quill allows any HTML, no sanitization before storage
**How to avoid:** Sanitize with DOMPurify before saving to database
**Warning signs:** `<script>` tags in database, alert() popups on event pages
**Example:**
```typescript
import DOMPurify from 'dompurify';

// Before saving to database
const sanitized = DOMPurify.sanitize(richTextValue, {
  ALLOWED_TAGS: ['p', 'br', 'strong', 'em', 'u', 's', 'a', 'ul', 'ol', 'li', 'h1', 'h2'],
  ALLOWED_ATTR: ['href', 'target', 'rel']
});
```

### Pitfall 5: Image Upload Without Progress Feedback
**What goes wrong:** User uploads large image, wizard appears frozen
**Why it happens:** No loading state during compression + upload
**How to avoid:** Show progress indicator, disable next button during upload
**Warning signs:** Users clicking "Next" multiple times, duplicate uploads

### Pitfall 6: Date/Time Zone Inconsistencies
**What goes wrong:** Event shows wrong time due to timezone conversion
**Why it happens:** Mixing local Date objects with ISO strings
**How to avoid:** Use combineDateTime and formatDateTimeLocalInput from jam-form.ts
**Warning signs:** Events off by hours, times change after save

### Pitfall 7: RecurrenceEditor Without Start Date
**What goes wrong:** RRULE generation fails or uses wrong dtstart
**Why it happens:** RecurrenceEditor needs startsAt but it's not set yet
**How to avoid:** Only show RecurrenceEditor after date/time fields are valid
**Warning signs:** Console errors about invalid RRULE, null reference errors

### Pitfall 8: Missing Preview Values Show as "undefined"
**What goes wrong:** Preview displays literal text "undefined" or "null"
**Why it happens:** Template literals don't handle undefined/null gracefully
**How to avoid:** Null coalescing and try/catch in format functions (Pattern 7)
**Warning signs:** Text "undefined" visible in UI, broken date formatting

### Image Upload with Compression
```typescript
// NEW implementation based on existing patterns
import imageCompression from 'browser-image-compression';
import { supabase } from '@/integrations/supabase/client';

const uploadEventImage = async (file: File) => {
  // Validate type
  const validTypes = ['image/jpeg', 'image/png', 'image/webp'];
  if (!validTypes.includes(file.type)) {
    throw new Error('Formato non supportato');
  }

  // Validate size (5MB max)
  if (file.size > 5 * 1024 * 1024) {
    throw new Error('File troppo grande (max 5MB)');
  }

  // Compress
  const compressed = await imageCompression(file, {
    maxSizeMB: 1,
    maxWidthOrHeight: 1920,
    useWebWorker: true,
  });

  // Generate unique filename
  const filename = `${crypto.randomUUID()}.${file.name.split('.').pop()}`;

  // Upload to event-images bucket
  const { data, error } = await supabase.storage
    .from('event-images')
    .upload(filename, compressed);

  if (error) throw error;
  return data.path;
};
```

## Open Questions

1. **Should image upload be required or optional?**
   - What we know: Bucket exists, optimization utils exist, EventCard shows fallback image
   - What's unclear: Product decision on whether events MUST have images
   - Recommendation: Make optional initially, validate adoption before requiring

2. **How many wizard steps should there be?**
   - What we know: Current has 3 steps (Type, Schedule, Preview)
   - Proposed: 5 steps (Type, Location/Details, Schedule, Image, Preview) or 4 (combine some)
   - What's unclear: User testing on optimal step granularity
   - Recommendation: Keep at 4 steps max to reduce cognitive load (Type+Location, Schedule+Recurring, Image, Preview)

3. **Should teacher selection happen in wizard or post-creation?**
   - What we know: TeacherSelect exists but requires eventId, currently post-creation
   - What's unclear: Whether storing teacherIds array in form state then adding after creation is acceptable
   - Recommendation: Add as optional step 3 for class/workshop types, implement batch insert after event creation

4. **How to handle auto-save with image uploads?**
   - What we know: useAutoSave debounces at 1000ms, upserts draft to database
   - What's unclear: Whether to upload image on selection or only on final submit
   - Recommendation: Upload immediately on selection (so draft has image), clean up orphaned images on draft deletion
