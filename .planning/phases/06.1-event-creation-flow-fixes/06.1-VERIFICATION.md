### Architectural Highlights

**LocationInput Pattern:** Uses presentational component pattern (receives predictions from parent) rather than self-contained Google Maps management. This is BETTER than typical implementations because:
- Separation of concerns (UI vs API logic)
- Parent controls session tokens and debounce
- Testable (easy to mock predictions)
- Reusable with any autocomplete source

**Auto-fill Logic:** End time auto-fills with non-destructive pattern (shouldDirty: false) to avoid marking form dirty on automatic suggestions.

**Conditional Wizard Steps:** Teachers step only shown for class/workshop/convention types, adjusting totalSteps dynamically (4 or 5 steps).

**Batch Teacher Insertion:** Client-side Promise.all wrapper over individual API calls avoids need for backend batch endpoint.
