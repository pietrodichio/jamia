Create railway.toml at repository root following research Pattern 4 (Selective Deployment Configuration):

```toml
[build]
builder = "NIXPACKS"
buildCommand = "pnpm install && pnpm build --filter=@jamia/backend"

[deploy]
startCommand = "cd apps/backend && pnpm start:prod"
watchPaths = ["/apps/backend/**", "/packages/**"]
```

Key configuration:
- buildCommand: Install all workspace deps, then build only backend using Turborepo filter
- startCommand: Change to backend directory and run production start script
- watchPaths: Trigger rebuild only when apps/backend or packages change (not apps/web)

Create apps/backend/.env.example documenting required environment variables:

```

Commit configuration:

git add railway.toml apps/backend/.env.example

- watchPaths ensures selective deployment
- Backend rebuilds only when apps/backend or packages change

```

Why watchPaths: Railway has native monorepo support. When git push occurs, Railway checks watchPaths. If changed files match paths, it rebuilds. If no match, it skips deployment. This prevents frontend changes from triggering backend rebuilds (MONO-05).

<task type="auto">

  <files>
    netlify.toml
    apps/web/.env.example
  </files>
  <action>
Create netlify.toml at repository root following research Pattern 4 (Selective Deployment Configuration):

```toml
[build]
  base = "/"
  command = "pnpm build --filter=@jamia/web"
  publish = "apps/web/dist"
  ignore = "git diff --quiet $CACHED_COMMIT_REF $COMMIT_REF apps/web packages"

[build.environment]
  NODE_VERSION = "22"
  NPM_FLAGS = "--version"
```

Key configuration:
- base: Build from repository root (not app subdirectory)
- command: Use Turborepo filter to build only frontend
- publish: Point to Vite output directory in apps/web/dist
- ignore: Exit 0 (skip build) if no changes in apps/web or packages directories
- NODE_VERSION: Match existing backend version (22.9.0 -> 22)
- NPM_FLAGS: Dummy flag to prevent npm usage (force pnpm)

Create apps/web/.env.example documenting required environment variables:
```
# Supabase Configuration (Public)
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=

# Backend API
VITE_API_BASE_URL=
```

Commit configuration:
```bash
git add netlify.toml apps/web/.env.example
git commit -m "feat(deploy): configure Netlify for monorepo deployment

- Uses Turborepo filter to build only frontend
- Ignore command implements selective deployment
- Frontend rebuilds only when apps/web or packages change

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>"
```

Why ignore command: Netlify lacks native watchPaths like Railway. Instead, use ignore command that runs git diff. If no changes detected in specified paths, command exits 0 (success), telling Netlify to skip build. This prevents backend changes from triggering frontend rebuilds (MONO-04).

IMPORTANT: The ignore command uses $CACHED_COMMIT_REF (last deployed commit) and $COMMIT_REF (current commit). These are Netlify-provided environment variables.
