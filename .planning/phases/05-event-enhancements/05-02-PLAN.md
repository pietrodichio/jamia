  <action>
Create Supabase migration for many-to-many teacher associations:

**1. Create event_teachers table:**
```sql
CREATE TABLE event_teachers (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  event_id UUID NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  role TEXT,  -- Optional: "lead instructor", "assistant", etc. (display only)
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(event_id, user_id)  -- One user can be teacher on event only once
);
```

**2. Create indexes for bidirectional queries:**
```sql
CREATE INDEX idx_event_teachers_event_id ON event_teachers(event_id);
CREATE INDEX idx_event_teachers_user_id ON event_teachers(user_id);
```

**3. Add comment documentation:**
```sql
COMMENT ON TABLE event_teachers IS 'Many-to-many junction table linking events to teacher/instructor profiles. Teachers are display-only metadata with no special permissions.';
COMMENT ON COLUMN event_teachers.role IS 'Optional role descriptor (e.g., "lead instructor", "assistant"). Display only, does not affect permissions.';
```

**4. Add RLS policy (no special permissions, anyone can read):**
```sql
ALTER TABLE event_teachers ENABLE ROW LEVEL SECURITY;

-- Anyone can view teacher associations
CREATE POLICY "Anyone can view event teachers"
  ON event_teachers FOR SELECT
  USING (true);

-- Only event owner/co-organizers can manage teachers
CREATE POLICY "Event owners can manage teachers"
  ON event_teachers FOR ALL
  USING (
    EXISTS (
      SELECT 1 FROM events
      WHERE events.id = event_teachers.event_id
      AND is_event_owner_or_organizer(auth.uid(), events.id)
    )
  );
```

Follow established patterns from existing migrations, particularly event_organizers table structure.
