```typescript
}

if (searchDto.accommodation_options && searchDto.accommodation_options.length > 0) {
  query = query.contains('accommodation_options', searchDto.accommodation_options);
}

if (searchDto.food_options && searchDto.food_options.length > 0) {
  query = query.contains('food_options', searchDto.food_options);
}

// ... rest of method (order by, execute query, return results) ...
```

**Note on contains operator:** Supabase client's `.contains()` method translates to PostgreSQL's `@>` operator, which uses the GIN index created in migration 05-03.

**Alternative if using RPC function:** If search still uses search_events_by_location RPC function, add tag parameters to RPC signature and add WHERE clauses:
```sql
-- In RPC function
WHERE (@p_tags IS NULL OR events.tags @> @p_tags)
  AND (@p_accommodation IS NULL OR events.accommodation_options @> @p_accommodation)
  AND (@p_food IS NULL OR events.food_options @> @p_food)
```

Research reference: PostgreSQL ARRAY @> operator with GIN indexes provides 10-50x performance vs junction tables (RESEARCH.md Pattern 6).
